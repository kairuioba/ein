# 3 分钟自测（任务式工作台 · dev 包）

目的：用真实操作确认「建任务 → 派单 → 需要你 → 通过/打回 → 基于此新建 → 只读窗口」这条链路。
不需要技术背景；任何一步卡住，把截图和侧栏文字发给总控即可。

## 准备
1. 打开 Ein（开发渠道 dev 包，版本 1.1.4-dev.x）。
2. 左侧应能看到「任务」列表；没有任务时显示「还没有任务——点 + 会在新窗口开一个任务」。

## 第 1 步：新建任务（约 10 秒）
1. 点「任务」右侧的 **+**。
2. 应自动跳到新对话窗口，任务列表顶部出现「新任务」。
3. 期望：任务是新窗口，不会混进旧对话。

## 第 2 步：给总控一个小任务（约 1-2 分钟）
在输入框发一句可快速完成的话，例如：
> 让团队写一句不超过 20 字的欢迎语，并说明理由，汇总成一页纸。不要改任何文件。

3. 总控会拆子任务并派给员工；任务行出现进度。
4. 期望：完成后任务状态变「已完成」，窗口提示「这个任务已完成，不再接收新消息」。

## 第 3 步：处理「需要你」（约 30 秒）
1. 左侧出现「需要你 N 件」时点开。
2. 卡片显示任务标题 + 一句话原因 + 证据；按钮是「通过，继续 / 打回，重做 / 稍后」。
3. 点 **通过，继续**：收件项消失，任务被确认。
4. 或点 **打回，重做**，写一句原因（如「第 2 点没有数据来源」）：任务会重跑一轮，重跑时会把这句话带给员工。

## 第 4 步：基于此新建（约 30 秒）
1. 回到已完成任务的窗口，输入框应替换为只读条：「这个任务已完成，不再接收新消息」+「基于此新建」。
2. 点「基于此新建」：应打开一个新的任务窗口，带一句可编辑草稿；旧聊天记录不会被复制。
3. 期望：旧任务仍在「已完成」里可查，新任务单独一行。

## 第 5 步：只读保护（约 10 秒）
在已完成任务的窗口里（如果还有旧的输入框）尝试发消息：
- 期望：不能发送，提示「已完成的任务不能再发消息；要继续请点『基于此新建』」，不会报错误码。

## 要记下的三件事（发给总控）
1. 哪一步和上面写的不一样（截图 + 侧栏文字）；
2. 收件箱点「通过」后，任务行是否变成「已完成」；
3. 「基于此新建」打开的新窗口，有没有出现旧的聊天记录（应该没有）。
