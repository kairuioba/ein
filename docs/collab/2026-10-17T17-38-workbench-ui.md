## 1. 三种运营模式

**A. 值班长模式（决策流）**
- **定义**：公司默认自己跑，App 只做一件事，把需要你的事排成一叠卡片，一次处理一张。
- **打开先看到**：一句状态句（"公司在自己运转：4 个在跑，1 件等你"），下面是最该处理的那张决策卡。
- **一天循环**：
  - 早 8 点看晨报句，清 1–3 张卡。
  - 白天被推送叫一次。
  - 晚上看"今天完成了什么"。
  - 随口丢一句新想法。
- **适合**：老板碎片时间、手机优先、任务多但每个都要点头的场景。
- **不适合**：老板想深度参与过程的创作型工作。
- **最大风险**：老板变成橡皮图章，只会点"批准"。所以要靠证据和按住确认来对冲。
- **颠覆程度**：删除侧栏、列表、独立收件箱。

**B. 目标合同模式（OKR/预算制）**
- **定义**：老板只定「本周目标 + 预算 + 红线」，AI 经理自己拆任务，老板只在目标层验收。
- **打开先看到**：3 个目标的进度条，加上预算燃烧速度。
- **一天循环**：周一定目标，周中看偏差，周五验收。
- **适合**：目标清晰、周期长的项目。
- **不适合**：临时碎任务多、需求飘忽的场景。
- **最大风险**：拆解错了，老板很晚才发现。AI 自己拆、自己验，容易整周跑偏。

**C. 幕僚长对话模式**
- **定义**：只有一个入口，也就是和"幕僚长"聊天；任务、评审、复盘都是聊天里长出来的卡片。
- **打开先看到**：幕僚长的一句话汇报，加输入框。
- **一天循环**：语音下指令，收汇报，追问"为什么"。
- **适合**：老板喜欢口述、不想学界面。
- **不适合**：需要批量处理、需要可审计留痕的场景。
- **最大风险**：状态藏在对话流里，翻不出来，积压不可见。

## 2. 推荐：A，并借 B 的一个字段

理由有三点：
- 你们已经有 gate、送回次数和 snooze，这些就是决策卡的原料，实现成本最低。
- 老板凌晨在手机上看，最稀缺的是注意力，而不是信息。
- A 的风险（橡皮图章）可以用现有证据机制化解。B 只借一个"任务必须挂目标"的字段，用来做复盘归因。

## 3. 保留与删除

**保留**
1. **gate 证据和送回计数**。这是防橡皮图章的核心，也是决策卡的主体。
2. **ReviewerPort 的诚实签收句**。把它放在卡片上，不要藏在详情里。
3. **snooze 语义**。并入决策卡的「明早8点再看」，保留"后来的事项会重新顶起提醒"的逻辑。

**删除或降级**
1. **侧栏任务列表**：手机上不成立。改成「全部」tab，加搜索和筛选，且不是首页。
2. **独立收件箱**：并入首页卡片栈。"收件箱"这个概念消失，只有"需要你"。
3. **工作台/团队地图**：移出首页，只在异常时露出一行。这是整套方案最需要老板拍板的取舍。
   - 任务窗口：改成单屏详情，不做多窗口。
   - 简报页：变成首页的那句状态句，加每天 8:00 的一条推送。

## 4. 运营规则（可落到状态机）

**状态机**：`idea → triaged → running → gate → needs_owner → done`，另有旁路 `sent_back`、`parked`、`stalled`、`cancelled`。

- **任务来源**四种：老板一句话、周期任务、外部事件，以及 AI 提议。AI 提议要老板一键采纳，每天最多 3 条。
- **负责人**：每个任务恰好 1 个 owner agent 和 1 个 reviewer。同一 agent 不得自评，这一条在权限层强制。
- **必须老板拍板**：
  - 不可逆操作或对外发布。
  - 花费超阈值。
  - 送回达 2 次以上。
  - 权限提升。
  - 其余走自动通道。
- **防堆积**：
  - running 数有上限。
  - "待老板"超过 5 张时，暂停 AI 提议和新建。
  - 待老板超过 24 小时，提醒一次。
  - 超过 72 小时自动 `parked`，不是自动批准。
- **防烂尾**：
  - 每个任务有完成定义和 TTL。
  - running 超过 30 分钟没有心跳，标 `stalled`，自动重试 1 次，再失败就升级到决策卡。
  - 超过 7 天没有状态变化，推「还要吗？」。
- **防重复**：创建时用标题和目标的相似度检索，命中就提示"合并到 #12？"。
- **老板不在时**，打开「离席模式」，规则如下：
  - 只能做可逆、不对外、预算内的事。
  - 自批的事项全部列入晨报，并带一键撤销。
  - 超时没人拍板一律 `parked`，默认安全。
  - 授权规则可由复盘页里的"以后自动批准同类"生成，有效期默认 14 天。

## 5. 只改一处就「哇」：首页单卡决策栈

- **改什么**：首页换成「一句状态句 + 一张决策卡 + 按住批准」。
- **实现（1–2 天，复用现有 inbox 数据，无新后端）**：
  1. 排序：风险 × 等待时长，取队首。
  2. 状态句用模板字符串拼接，用现有计数，不调 LLM。
  3. 「按住 0.6 秒」用 pointer 事件加 CSS 进度环，松手取消，避免手机误触。
  4. 卡片展示 gate 证据行和"批准后会发生什么"，数据来自现有 gate 字段，缺的字段先写死文案。
  5. 批准后卡片飞走，下一张补上；清空时显示"今天没有事找你了"。
- **「哇」在哪**：凌晨 2 点单手 5 秒清完，而且每一步都有证据。

## 6. 成功指标（用状态时间戳即可算）

1. **决策延迟**：`needs_owner` 进入到老板动作的 p50/p90。目标是 p50 小于 1 小时、p90 小于 24 小时。
2. **烂尾与积压**：待老板积压数，加上 7 天无状态变化的任务占比。目标是积压不超过 5，烂尾占比低于 10%。
3. **首次通过率**：第一次送审就批准的比例，加上送回原因的分布。如果批准率逼近 100% 且决策耗时极短，要警惕橡皮图章，那是退步信号。

**反问**：老板主要在手机上用，还是桌面为主？如果手机只是看，桌面才是干活的地方，屏①的"按住批准"和桌面的差异化要重新取舍。
