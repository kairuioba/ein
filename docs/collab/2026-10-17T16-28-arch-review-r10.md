## 1. 任务行展开（先看"现状和要我做什么"，再看产出）

折叠态保持不变：`● 标题  [要你确认 1]  小明`。

展开后：
```
给官网加暗色模式                      小明 · 进行中 2 天
现在：正在改样式，下一步自测
等你：1 件 ——「是否可以上线」          [去处理]
已交出：3 个文件 · 1 份说明
[打开任务窗口]                     更多 ▾（做到什么算完成 · 过程记录）
```
- 顺序依次是：现状一句话、等你的事、产出、入口。
- "更多"里才放：验收标准（叫"做到什么算完成"）、尝试次数（叫"过程记录"，用"第 2 轮"代替 attempt）、参与者、时间线。
- 用词替换：闸门→"确认"；criteria→"做到什么算完成"；attempt→"第 N 轮"；needs-you→"要你确认"（角标和收件箱统一用这一个词）。

## 2. 已完成任务的输入区

不要把输入框置灰，灰框会诱导老板去打字。把整条输入区替换成一条状态栏：
```
┌──────────────────────────────────────────┐
│ 🔒 这个任务已于 10月16日 18:20 完成，不再接收消息 │
│ [        基于此新建        ]  查看复盘 →  │
│ 会带上结论和成果文件，不带聊天记录          │
└──────────────────────────────────────────┘
```
- 「基于此新建」是主按钮，放在原发送按钮的位置，手机上占满宽。
- 「查看复盘」是次级文字链接，放在主按钮右侧或下方。
- 小字说明"带什么、不带什么"，对应你们"只传 accepted 内容"的规则。老板最怕新任务继承了一堆旧乱账。
- 409 兜底文案：「已完成的任务不能再发消息。要继续，请点『基于此新建』。」不要露出 409 或任何错误码。

## 3. 复盘页第一屏（4 项，加一行头部）

头部一行：`标题 · 负责人 · 用时 · 打回 N 次`。

第一屏 4 项：
1. **结果**：一句话结论，加"已完成 / 未完成"徽标。
2. **交付了什么**：最多 3 个产出物，可点开，其余显示"另有 N 个"。
3. **你拍过的板**：你通过、打回过什么，打回的原文原样显示。老板最关心的是"我当时说了什么，有没有被听进去"。
4. **留下的事 / 下一步**：来自 handoff，是尚未解决的问题。

折叠区（默认收起）：完整会话、每一轮的详情、工具调用、证据原文、context share 来源。

「基于此新建」放两处：
- 手机上放底部吸底按钮。
- 第 4 项"下一步"的末尾再放一个，文案是「按这个下一步新建」，这时 handoff 可以预填成新任务的第一句话。

## 4. "需要你"在手机上的形态

**一次一个的全屏卡片**，不要列表弹窗。
- **入口**：页面顶部或底部固定一条常驻条"3 件等你确认"。页面内强提示，加标签页标题闪烁和角标（见上面的安全上下文限制）。
- **卡片**：顶部显示 `1/3`，中间显示标题、一句原因和最多 3 条证据，"看全部证据"点开后用底部抽屉展示。
- **按钮**（拇指区，吸底）：
  - 「通过，继续」和「打回，重做」等宽并排。
  - 「稍后」做成文字链，权重更低。
  - 打回时抽屉弹出一个输入框，带"一句话说明"的 placeholder，用手机输入法自带的语音输入即可。
- **防误触**：通过后给 5 秒的"已通过 · 撤销"提示条，客户端延迟 5 秒再真正提交。
- **手机能做**：通过、打回（一句话）、稍后、浏览复盘、基于此新建（不选 context 的默认版）。
- **必须回电脑**：
  - 通过后会触发不可逆动作的确认（上线、合并、对外发送）。
  - 强制放行（gate override）。
  - 大段 diff 或多文件证据的核对。
  - 修改验收标准。
  - fork 时手选 context。
  - 关闭或删除任务。
- 这些电脑专属项在手机上不要藏起来，要显示成「请在电脑上处理」的灰按钮，并写明原因。

## 5. 冒烟后让我报告的三项证据

1. **真机实录**：用 375px 宽的真手机（不是浏览器缩窗），从收到"要你确认"到点完通过或打回，记录步数、耗时，以及有没有横向滚动、文字截断、误触。
2. **完整生命周期的原文记录**：创建任务，到要你确认，到打回，到通过，到 closedAt，再到发消息得到 409。要附三样东西：
   - 打回那句话在 agent 下一轮里被引用的原文。
   - 409 时 UI 实际显示的文案。
   - 「基于此新建」后新窗口的 context 实际只含 accepted 内容的证据。
3. **多端一致性**：电脑和手机同时开着，
   - 一端处理后另一端的计数延迟是多少秒。
   - 断网重连后收件箱数字与后端是否一致。
   - 两端同时点同一条会怎样（重复提交、静默覆盖，还是友好提示）。

可以顺手附一个零成本检查：全站 UI 文案里"闸门 / criteria / attempt / 409"这类词的残留数。

## 6. 最容易让老板困惑或误操作的点

- 最危险的是「通过」这个词。老板可能把它理解成"这事办完了 / 可以对外发了"，其实只是"同意继续下一步"。
- 修法：按钮带宾语和后果，写成「通过，继续」「打回，重做」，卡片上再用一行小字写明后果，例如"通过后小明会开始下一步：上线检查"。
- 次要风险：点任务行会把 Bot 的活跃会话切走，老板会以为原对话丢了。
- 次要风险的修法：任务窗口顶部固定一条"你正在看「任务名」· 返回主对话"，并在切换前后都保持这条可见。
