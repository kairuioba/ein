# 一念 Ein 1.1.2 使用手册

> 「一念起，万 Bot 动」。这本手册讲 1.1.2 的安装、这次修了什么、怎么验证，以及只在你自己电脑上出现的「维护岗 / 开发版」怎么用。

## 1. 安装与更新（Mac）

**已经装过一念**

- 打开一念，它会自己检查更新：下载 1.1.2 后，退出时装上，下次打开就是新版本。
- 也可以手动检查：设置 → 更新 →「检查更新」。

**全新安装**

1. 打开 https://github.com/kairuioba/ein-releases/releases/latest。
2. 选安装包：Apple 芯片（M1–M4）下载 `arm64.dmg`，Intel 下载 `x64.dmg`。
3. 打开 dmg，把「Ein」拖进「应用程序」文件夹，再从「应用程序」里打开。必须拖进去，自动更新才能替换它。
4. 第一次打开时，Mac 会提示「无法验证开发者」：到「系统设置 → 隐私与安全性」点「仍要打开」，只需一次。

**Windows**：同一页面下载 `setup.exe`，双击安装。

## 2. 引擎与登录

一念只用你自己的官方账号来驱动各家模型：

| 引擎 | 怎么登录 | 不算登录、也不会拿来跑任务的 |
|---|---|---|
| Claude | 终端运行 `claude auth login --claudeai`，在打开的官方网页里登录你的 Claude 订阅（Pro / Max） | API Key、Anthropic Console 账号、`~/.claude/settings.json` 里的中转 Token、apiKeyHelper、Bedrock / Vertex |
| Codex | `codex login`，选 ChatGPT 登录 | OpenAI API Key 登录 |
| Grok | `grok login`（grok.com 账号） | xAI API Key（它属于单独的「Grok (API)」引擎） |
| 其他 | 各自 CLI 的官方登录 | — |

设置 → 引擎里会显示每个引擎的状态。如果 Claude 显示「需要登录」，卡片上会写明发现了什么（比如「用的是 settings.json 里的 ANTHROPIC_AUTH_TOKEN」）以及怎么处理。

## 3. 1.1.2 修了什么，怎么验证

| 以前的问题 | 现在 | 怎么验证 |
|---|---|---|
| Claude 没有 Opus 5.5 | 直接读取你装的 Claude Code 自己的模型菜单 | 选模型 → Claude，能看到 Opus 5.5、Sonnet 5.5、Haiku 5.5、Fable 5.1 |
| Grok 没有 4.7 | 跟随 Grok Build 自己的清单 | 先用 Grok 聊一句，之后选择器里出现 4.7（以及 xAI 新出的型号） |
| 改设置后反复出现「回合已中断——服务商设置已更改」 | 只重建真正改了的引擎 | 机器人干活时切换「推荐策略」，它不会被打断 |
| Claude 走了 API 计费 | 只认订阅登录 | 用 API Key 登录的 Claude Code 会显示需要登录并说明原因 |
| 对话「顿」、最后一句被输入框挡住 | 绘制前就滚到底；流式只重绘当前气泡 | 让机器人写一大段，滚动应当平滑，最后一行完整露在输入框上面 |
| 新对话没出现在左下列表 | 选中的对话会自动滚到可见位置 | 点「新对话」，左侧列表里能看到并选中它 |
| 插话显示「已排队」 | Claude、Codex、Grok、WorkBuddy、Kimi 等直接插入当前回合 | 机器人干活时发一句话，会立刻出现在对话里，机器人在下一步就能看到 |
| 派单逻辑 | 修了 11 处（详见仓库 `docs/dev-edition-plan.md`） | 派一个跨部门的任务，看主管、员工、依赖、汇报是否正常 |

还会排队的引擎：pi、Antigravity、API 类引擎（Grok API、OpenAI 兼容、MiniMax）。群聊的输入框也仍然会排队。这些留到下一版。

## 4. 维护岗与开发版（只在你的电脑上）

### 4.1 打开维护岗（一次性准备）

1. 安装 GitHub CLI：`brew install gh`（没有 Homebrew 就先装 https://brew.sh）。
2. 登录：`gh auth login`，选 GitHub.com → HTTPS → 用浏览器登录 kairuioba 账号。
3. 下载源码：`gh repo clone kairuioba/ein ~/Ein-src`。
4. 重新打开一念 → 设置，左侧会多出「维护岗」。只有能推送 kairuioba/ein 的账号才会看到，用户的电脑上没有这一项。
5. 在维护岗里：
    - 填源码路径，例如 `/Users/你的用户名/Ein-src`；
    - 选一个引擎（推荐 Claude 或 Codex）；
    - 点「设置维护岗」。研发部里会出现「Ein 维护」机器人。

文件夹里的 `维护岗快速设置.sh` 会替你做第 1–3 步：在终端运行 `bash 维护岗快速设置.sh`。

### 4.2 修 bug 的流程

1. **报 bug**：在「Ein 维护」的对话里描述问题，可以附截图。也可以告诉总控，让它派过去。
2. **它来改**：
    - 复现问题，说清根因；
    - 开分支 `fix/<主题>` 修改；
    - 跑测试和中文化检查。测试不过不会往下走。
3. **你批准推送**：推送算「对外发布」，它会先问你。
4. **发开发版**：维护岗 →「构建与发布」，填分支名，点「发开发版」→「确定」。大约 30 分钟后，开发渠道的电脑会收到更新。
5. **在你的客户端核实**：
    - 维护岗 → 更新渠道选「开发版」，然后重启一念；
    - 等它收到 `1.1.3-dev.N` 并装上，就能试新改动。
6. **不满意**：继续让它改，再发一个开发版。也可以把渠道切回「正式版」并重启，回到最新正式版（这就是回退）。
7. **发布正式版**：核实无误后，让「Ein 维护」把分支合进 main、把版本号加一。然后在维护岗点「发布正式版」→「确定」，所有用户都会更新。

### 4.3 备份与找回

- 每次构建（开发版和正式版）都会在源码仓库打一个标签 `backup/v<版本>`，那一版的源码随时能原样找回。
- 每个开发版的安装包都留在 GitHub 的预发布里，想装回任何一个旧开发版，直接去下载。
- 规则全文见同一文件夹里的《GitHub 版本与备份规则》。

## 5. 常见问题

- **设置里看不到维护岗**：在终端运行 `gh auth status`，确认登录的是 kairuioba；然后在维护岗页面点「重新检查」（或重启一念）。
- **切了开发版渠道却没收到更新**：确认已经重启一念，并且构建在 GitHub 上跑完了（维护岗 → 构建与发布 → 运行记录里的链接）。
- **开发版改坏了**：渠道切回正式版并重启，回到最新正式版。源码用 `backup/v<版本>` 标签找回（见规则文档）。
- **Claude 一直显示需要登录**：按卡片上写的处理，比如删掉 `~/.claude/settings.json` 里 `env` 下的 `ANTHROPIC_AUTH_TOKEN` / `ANTHROPIC_API_KEY`，再运行 `claude auth login --claudeai`。
