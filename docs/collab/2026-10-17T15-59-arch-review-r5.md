**与你不同的地方：**

- **D1（观点 2 的理由）。** 我不认为反馈传不了「怎么写」。带具体示例的 hint，比如「把这句换成一个具体意象，例如……」，弱模型是能执行的。真正的上限有两个来源：
  - 评审不对称：它能指出缺陷，指不出「缺了灵气」，所以弱模型会停在「无缺陷但平庸」。
  - 反馈是局部的，而审美问题多是全局的（结构、语气统一、节奏），fixHint 逐条修只会修出补丁感。
  - 所以上限取决于「评审能表达多具体」乘以「弱模型能执行多少」，不是弱模型自身水平。创意类的结论不变，但机制不同，对应的补救手段也不同（见 D3）。
- **D2（观点 4 的成本）。** 主脑只重写关键段落的成本很低：它读全文是便宜的输入，只输出被替换的 span。真正贵的是「每轮强模型评审」。主脑重写比一开始用强模型更贵，只发生在两种情况：重写占比超过约 40%，或者评审超过 2 轮。
- **D3（观点 3 的解法）。** 治模板化靠结构，不靠限制轮数：
  - 把验收项拆成硬约束（清单）和品味项（只给方向，不给逐句改法）。
  - 品味类用 best-of-N 加强模型挑选，不用迭代修补。选择保留多样性，修补会收敛到清单。
- **D4（新增）。** 老板的前提是「主脑判得准」，这需要先验证。用 20 条人工标注样本测评审与人的一致率，一致率不够就不能当闸门。

## 2. 把「主脑当教练」放进闸门 v1

**加：**
- `fixHint` 结构化：`{criterionId, anchor(span/引文), severity, kind: must|suggest, scope: local|global}`。每轮只取 top-3 按严重度排序，只重做失败的 span，不整篇重来。
- 判决三态：`pass | fail-fixable | fail-escalate`。
- **每轮重跑全部检查项**，代码比对逐项向量。修好 A 却弄坏已通过的 B，这一轮作废，不接收。
- 无进展检测：同一项连续两轮失败且产物变化小，直接升级，不走第三轮。
- **教练与终审分离：** 终审用全新上下文的另一次调用，不能由给出 hint 的那次调用来判。否则它会对「响应了自己建议」的修改放水。
- 轮数和预算上限由代码持有，不由评审说了算。

**砍：**
- 自由文本的多轮对话式反馈。
- 把全部历史 hint 堆进 prompt。只给最新产物加当前 hint，历史累积会让弱模型漂移。
- 品味项的逐句 fixHint。
- 用评审给的分数当收敛条件。

**与代码聚合裁决不冲突，前提是：** fixHint 是旁路载荷，不进入裁决函数。裁决只来自逐项 pass/fail。冲突只会出现在评审能说「基本通过，建议微调」时，所以必须禁止第四种状态。另一个风险是评审有无限教练下去的倾向，这由代码的轮数上限来防。

## 3. 失败后允许主脑直接改到合格

**我的看法：值得做，但作为受控的末级兜底，不能是默认路径。**

- **成本：** 它严格优于「失败就让强模型整篇重做」，只要失败 span 的 token 占比 f 小于约 0.4。f 大于 0.4 就整篇重做，否则补丁式重写。
- **质量风险：** 弱模型的骨架会锚定强模型，产生语气接缝。让主脑读全文，同时修过渡句。
- **可审计性：这是最大的问题。** 「主脑重写，代码只核对验收项」让作者和裁判合一。必须补三样：
  1. 记录重写前后的 diff，产物标 `authoredBy` 及各自占比，并绑定到现有的 attempt identity。
  2. 验收由独立于重写者的检查器执行（代码检查，加全新上下文的 judge）。
  3. 事实性硬约束由代码保护，比如数字、专名、引用必须与重写前一致，防止重写引入幻觉。
- **重写占比本身要进路由遥测。** 占比高说明便宜手脚在这类任务上白跑了，应该直接改走强模型。

## 4. A/B/C 实验

**臂：**
- A：强模型直接做。
- B：弱模型加强评审，一遍判 pass/fail，不带 hint。
- C0：弱模型加 fixHint，最多 2 轮，不润色。
- C：C0 加主脑润色。
- 可选 D：弱模型 best-of-3 加强模型挑选，用来验证多样性假说。

C0 的作用是把「教练的贡献」和「润色的贡献」拆开，否则你无法归因。

**样本：** 三层任务各 4 个，共 12 个。可机检、半可检（带事实清单的报告）、品味类（文案、故事开头）。产出压到 500–800 字，成本最低。同一 prompt 配对跑所有臂。n=12 每层只能检出大效应（胜率 75% 以上），小差异不要下结论。

**指标：**
- 主指标：盲评成对偏好。judge 用与评审不同的模型族，并交换位置。品味层由老板本人盲评，一个下午 15 分钟，这才是 ground truth。
- 副指标：
  - 硬闸门通过率（代码）。
  - 实际 $（从日志的 in/out token 乘价格表，含重试和评审）。
  - 墙钟时间、轮数。
  - 重写占比（编辑距离）。
  - **Goodhart 探针：** 清单得分与盲评偏好的差。清单分升而盲评不升，就是在套模板。
  - **模板化：** 同模板任务间的 distinct-n、self-BLEU，加上 rubric 用语回声率。

**省额度：**
- 第 0 步：先用 `docs/collab/transcript.jsonl` 和历史运行回放，估计各任务类型的 q1，几乎零成本。
- 第 1 步：只跑弱模型，先拿到 q1。强模型调用只花在弱模型过不了闸门的任务上，臂 B、C 的成本随之按条件缩减。
- 序贯停止：品味层前 6 个任务里 C 不优于 B，就砍掉 C 在该层的预算。
- 上线后用 `gate.coach` 开关做 shadow 模式，在真实任务子集上同时记录两条路径。

## 5. 成本公式与决策规则

令 S 为强模型直接生成的成本，归一化为 1。

- r：弱模型输出价与强模型输出价之比。
- ρ：强模型输入价与输出价之比，假设约 0.2，用真实价目表代入。
- h：fixHint 输出相对产物长度的比例，约 0.1。
- q1：弱模型首轮通过率。
- q2：一轮教练后通过率。
- φ：重试时只重做失败 span 的占比，约 0.4。

首轮成本 = `r + ρ + h`。重试成本 = `φ·r + ρ + h`。

```ts
function useCoachPath(p: {r:number; rho:number; h:number; q1:number; q2:number;
                         phi?:number; reviewIsCode?:boolean; tasteCritical?:boolean}) {
  const { r, q1, q2, phi = 0.4, tasteCritical } = p;
  const rho = p.reviewIsCode ? 0 : p.rho, h = p.reviewIsCode ? 0 : p.h;
  const first = r + rho + h;
  const retry = phi * r + rho + h;
  const E = first + (1 - q1) * retry + (1 - q1) * (1 - q2) * 1.0; // 末项：升级到强模型
  if (tasteCritical) return false;       // 关键审美段走强模型，弱模型只填充
  return E < 0.65 && q1 >= 0.4;          // 留 35% 余量覆盖延迟和方差
}
```

**数值直觉：** 取 r=0.1、ρ=0.2、h=0.1、q1=0.6、q2=0.7，则 E≈0.66，只省三分之一。q1=0.3 时 E≈0.85，不划算。r 大于等于 0.3 且评审靠强模型时几乎永远不划算，因为单轮评审就是 0.3。**当评审是代码（测试、schema）时 ρ 和 h 都为 0，只要 r 明显小于 1 就划算。**

**推论：** 强模型评审是成本地板。降本的杠杆是分层评审：代码和中档模型跑绝大多数检查项，强模型只在终审跑一次品味项。

公平对比时，臂 A 也要加上同样的闸门评审成本，否则会高估便宜路径的优势。
