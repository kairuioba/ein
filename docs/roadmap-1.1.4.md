## B. 待实施（建议顺序）

### 1. 任务式工作台（新，老板最关心）
- 设计：`docs/task-centric-workbench.md`（含对同类产品截图的分析：学了信息组织方式，不照搬；差异化在派单总库/验收/复盘）
- 新增要点：任务头部上下文条、对话内「任务团队」条、任务启动前确认卡（Charter+验收人）、按就绪度分层的任务看板、运行报告
- 已确认硬规则：一个 Bot 只属于一个任务；第二个并行任务新建 Bot；任务负责人 ↔ 总控协调；快 Bot 重新派活（部门其他任务/辅助慢任务）
- 第二轮确认：总控在所有任务之上、直接向老板汇报；**任务负责人 ≠ 总控**（任务级权限）；同部门空闲同事可主动辅助慢同事（不需要负责人逐条下令，数据独立场景除外）；已完成任务暂不归档
- 快同事经验提炼/复现：研究稿 `docs/fast-worker-skills.md`（本版不做，下个版本按阶段 1 实现）
- UI 草图：`docs/mockups/`（侧栏三级分层 / 任务式工作台 / 任务内调配与总控协调）
- 阶段：① 工作台任务选择器（只读）→ ② TaskFolder 持久化 + 侧栏文件夹 → ③ 部门归属任务 → ④ 派单自动建任务文件夹 → ⑤ 通知/指标按任务隔离
- 验收：给总控一个任务 → 侧栏出现带颜色/序号的任务文件夹；打开工作台只看这个任务；多任务不混排。

### 1.4 对标 Claude Code 的多 Agent 协同（新）
- 分析：`docs/claude-code-multi-agent-analysis.md`（社区逆向 + 官方文档；抖音原视频本机打不开，已注明）
- 最该吸收：角色模板库、按角色工具权限、强制 Handoff 契约、总控上下文纪律、验证闸门
- 不照搬：单主 Agent、无限子 Agent、自由文本结果、它的 UI

### 1.5 中途换模型的上下文交接（新，设计已完成）
- 设计：`docs/model-switch-handoff.md`
- 核心：换模型不重放历史，交接包 ≤1200 tokens（目标/当前子任务/最新 Handoff/产出引用），切换前显示 token 与费用估算；派单子任务只对「未开始」的换模型
- 阶段：① 交接包构建器 ② 聊天换模型确认卡 ③ 检索工具 ④ 指标与回退建议

### 2. 验收闸门（自我迭代阶段 2）
- 员工交结果后由 `reviewer` 按 `acceptance` 判 pass/fail；不过退回重做/换模型，过了才进汇总；
- 与任务式工作台的「任务验收」共用同一套结果。

### 3. 长任务阶段 B–E
- B：Handoff 结构化交接（done/evidence/decisions/openQuestions/nextStep）；
- C：定时监督 routine（每 N 小时更新 State Doc、重规划、漂移检测、停损）；
- D：上下文装配器（预算 + 注入清单 + 检索）；
- E：多天恢复/换引擎压测（**老板亲自测，我不擅自跑长任务**）。

### 4. 自我迭代阶段 3–4
- 3：派单总库检索与模板注入 + 失败模式归并；
- 4：维护机器人按失败模式提案 → dev → 老板验收 → 转正（半自动改代码）。

### 5. 派单审计剩余两项
- 部门隔离完整化（跨部门脱敏/申请访问）；
- 诊断聚合 child run（部门自己的计划）。

## C. 测试与发布分工

- 我做：单元测试、typecheck、i18n、构建、dev 安装、可自动化的 UI 走查；
- 老板做：真实长任务测试、模型/账号相关验证、每次发布的最终验收；
- 正式版：合 main + 升版本 + 发布，**必须老板明确说「发布正式版」**；发布前自动跑 verify 门槛。

## D. 建议下一步（只等一句话）

1. 任务式工作台阶段 1–2 先做（看得见的整理效果）；
2. 验收闸门紧随其后；
3. 长任务 B–E 老板亲自测后再排；
4. 正式版等老板验收 dev 后发布。
